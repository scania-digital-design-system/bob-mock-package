# ADR 0001: Package Skeleton

**Status:** Accepted. **D1, D2 and D3 superseded by ADR 0002**; D4–D7 stand.
**Scope:** package

## Context

This repo packages React cells generated by the brand-orchestration-backbone pipeline
from Tegel-derived payloads, and measures them against `@scania/tegel@1.66.1`. The shape
of the delivered cell drives the packaging:

- A React cell is `component.jsx`, `component.css`, `tokens.js`, `metadata.json`,
  `api.json`, `a11y.json` and `usage.jsx` (backbone `pipeline/src/client/layout/layout.go`,
  `FileExtensions`: React is `.jsx` + `.js`).
- The React bootstrap prompt (`pipeline/prompts/bootstrap_system_react.txt`) asks for "no
  import and no export statement". A bootstrap `component.jsx` may therefore be a bare
  function that cannot be imported as delivered. Whether the pipeline wraps it later is
  unverified until the first run.
- Cells are generated and stay byte-for-byte as delivered (CLAUDE.md rule 4), so anything
  the package needs beyond the cell happens in our build, not in the cell.
- Only React is in scope, but an Angular target must be addable later.
- Tegel's web components render in shadow DOM, which jsdom does not render faithfully.

## Decision

**D1 — Name and registry guard.** The package is `@umain-mock/bob-tegel-react`.
`publishConfig.registry` is `http://localhost:4873` (Verdaccio), so a bare `npm publish`
cannot reach public npm. A future Angular package is `@umain-mock/bob-tegel-angular`.

**D2 — Layout.**

```
payloads/<component>.json              # hand-written from Tegel source at the pinned tag
cells/<target>/<component>/scania/v<n>/ # pipeline output, copied byte-for-byte
src/index.ts                           # hand-written re-exports
tests/<component>.test.tsx             # comparison tests against @scania/tegel
docs/adr/                              # decisions
docs/findings/<component>.md           # where a cell differs from Tegel
```

`cells/` mirrors the pipeline's own target-first output layout, so Angular cells land in
`cells/angular/` with no move.

**D3 — Build: Vite library mode.** ESM output, one CSS file, `.d.ts` for our TypeScript.
Vite handles `.jsx` and CSS imports natively, and Vitest shares its transform. If a cell
has no `export`, a build-time transform scoped to `cells/` adds it in the build output;
the source file is untouched. That transform is decided after the first cell is seen.

**D4 — Tests: Vitest + jsdom + Testing Library.** DOM tests per cell, and a props check
of each cell's `api.json` against Tegel's `.d.ts`. Visual side-by-side comparison
(Playwright) is deferred until a cell exists, and gets its own ADR.

**D5 — Lint, format, typecheck: Biome + strict `tsc`.** Biome matches the backbone's own
TypeScript module (`figma/`). `cells/` is excluded from Biome and from `checkJs`: lint
findings in generated code are not ours to fix.

**D6 — Runtime.** Node 22 and npm. React 19 as a dev dependency (matches
`@scania/tegel-react@1.66.1`); peer dependency `react ^18 || ^19`.

**D7 — First component: badge.** Badge goes through bootstrap, the path four of the five
components take. Button resolves through the only blessed React template, whose API is
`label` and `onClick`, so it shows the template path, not how a component is created.
Order: badge, button, link, spinner, card.

## Alternatives considered

- **tsup instead of Vite.** Lighter for a pure TS library, but weaker CSS handling, and a
  second transform beside Vitest's.
- **npm workspaces now (`packages/react`, later `packages/angular`).** Cleaner once two
  targets exist; premature with one. Revisit when Angular is added.
- **One package with `./react` and `./angular` subpaths.** Forces Angular and React peer
  dependencies onto every consumer; Tegel itself ships separate packages.
- **ESLint instead of Biome.** Tegel uses ESLint; the backbone's TypeScript uses Biome.
  The process reference wins.

## Consequences

- Positive: one toolchain for build, dev server and tests; no route to public npm by
  accident; Angular slots into `cells/angular/` and a sibling package.
- Positive: generated code never trips our lint, so lint stays meaningful for hand-written
  code.
- Negative: no visual comparison until Playwright is added; jsdom tests check structure
  and classes, not appearance.
- Negative: the export transform in D3 is an open item; if needed it is hand-written build
  code with its own tests.
- Negative: React 19 in dev but `^18` in the peer range means React 18 is not exercised.
